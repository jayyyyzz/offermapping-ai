## 1. 本轮目的

Smoke 资格赛确认了 GPT、Claude、Qwen 可以进入下一阶段。本轮使用 6 条新的合成边界案例检查：

- 否定句是否污染相邻技能证据；
- 简历提示注入是否被执行；
- SQL 同名文本是否被误认为数据库经验；
- 普通“提示词”是否被误认为 Prompt Engineering；
- 模板数字是否被误认为个人成果；
- 技能清单、阅读文档、观看演示、工具安装和真实项目证据能否区分。

## 2. Gold 修订

首次 canary 暴露出 Dev v1.0 与 `extractor_v3` 证据规则不一致。三个模型同时把“只读文档、只看演示、只听说过、只安装工具”判为 `missing`，而原 Gold 部分标成了 `listed-only`。

因此冻结 `dev_v1_0.jsonl`，升级到 `dev-v1.1`：

- 只读文档、只看演示、只听说过、只安装工具统一为 `missing`；
- 技能清单、完成课程/教程、明确知识描述为 `listed-only`；
- 没有“优先/加分”限定、明确写在技能要求中的 FastAPI 修正为 `must`。

原始模型输出直接重新评分，没有为 Gold 修订重复调用 API。

## 4. Prompt v4 改动

`extractor_v4` 新增：

1. 否定句只约束明确否定的技能，不能抹掉相邻句中独立存在的可迁移证据。
2. 明确区分技能清单、课程/教程、文档阅读、观看演示、听说和工具安装。
3. “理解”不自动等于 nice；技能要求中没有局部加分限定时按 must。
4. 明确 OfferMapping 岗位族：应用层评测、RAG、Agent、LLM 后端、工作流和部署归入 `ai_app_dev`。
5. 明确“只在技能清单里写过名称”仍属于 `listed-only`。
