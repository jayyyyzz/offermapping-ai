# GPT Extractor 延迟稳定性报告

> Case：`ai_app_dev_boundary_injection_011`  
> Profile：`codex-gateway` / `gpt-5.5`  
> Prompt：`extractor_v4`  
> 数据：合成 Smoke 边界案例  
> 目的：稳定性观察，不代表完整 Dev 资格赛或线上 SLA

## 结果

本轮连续调用 3 次，全部成功并通过 Extractor 门禁：

| 指标 | 结果 |
|---|---:|
| 请求成功率 | 100% |
| 延迟 | 17.1s、18.4s、45.9s |
| 中位数 | 18.4s |
| 最大值 / 本轮 P95 | 45.9s |
| Schema 失败 | 0 |
| 门禁失败 | 0 |

历史同一案例记录为 16.7s、17.6s 和 116.3s。新一轮没有重现 116 秒级异常，但仍存在约 2.5 倍的长尾波动。

## 判断

- 不能把 20 秒作为可靠线上超时阈值；本轮有一条 45.9 秒响应。
- 如果产品需要稳定交互，建议采用“前端异步状态 + 后端 90–120 秒硬超时 + 可重试”设计。
- 评测层继续记录每次 latency、网关、模型和 token；不要用单次均值代替 P95。
- 完整 Dev 资格赛前，至少再对 3–5 条长上下文/提示注入案例各做 3 次重复。
