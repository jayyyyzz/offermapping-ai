## Design Context

### Users

- Primary: Chinese university students, new graduates, and career-switching interns who want to enter AI roles but lack strong project evidence.
- Core job: paste a target JD and resume, understand the evidence-backed gap, and leave with a realistic project roadmap that improves both the resume and interview depth.
- Context: users are often anxious, unsure which AI role fits, and easily overwhelmed by generic advice. The first-run experience must create clarity before asking for an account.

### Brand Personality

- Clear, trustworthy, action-oriented.
- Voice is calm and direct, using plain Chinese and specific evidence. It should feel like a thoughtful career coach, not an automated score generator.
- Never promise an offer. Explain what the score means, what can be changed, and what should be done next.

### Aesthetic Direction

- Light-first interface with warm tinted neutrals, ink-like typography, and one restrained green accent for forward progress.
- Editorial clarity meets a practical planning tool: asymmetric composition, visible evidence, and roadmap-like visual anchors.
- Mostly square-to-gently-rounded geometry; no neon AI gradients, glassmorphism, glowing dark dashboards, or generic card grids.
- Motion is limited to meaningful analysis progress and small state transitions, with reduced-motion support.

### Implementation Defaults

- New project. Product PRD specifies a React SPA; use Vite + React + TypeScript as the frontend baseline.
- Styling follows the React fallback: Tailwind CSS with a Base UI/shadcn-style compositional direction, customized to the OfferMapping visual system rather than shipped as stock components.
- Forms default to TanStack Form when form state grows beyond simple local validation.
- Tables/data grids default to TanStack Table; long or virtualized lists default to TanStack Virtual if those needs appear.
- Prefer local workflow-specific primitives for this small MVP surface; add block libraries only when they save real implementation time without flattening product hierarchy.

### Design Principles

1. Show evidence before advice: every diagnosis should visibly connect to the JD or resume instead of asking users to trust an opaque score.
2. Make the next action obvious: the primary screen should lead from gap to a concrete first project step, not end at analysis.
3. Separate changeable skills from hard constraints: do not let immutable requirements distort the progress score or imply that a project fixes everything.
4. Reduce anxiety with structure: use progressive disclosure, clear stages, and realistic time estimates instead of dense AI output.
5. Prefer honest specificity over motivational copy: no offer guarantees, fake certainty, or generic encouragement.
