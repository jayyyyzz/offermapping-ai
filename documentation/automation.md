# 模型工作流与自动化边界

## 工作流清单

| 工作流 | 触发者 | 自动性 | 可读取输入 | 可调用 API | 应用拥有的副作用 |
|---|---|---|---|---|---|
| Extractor v5 | 用户提交分析 | 用户明确提交后自动 | JD、简历、技能本体 | 配置的 OpenAI-compatible `/chat/completions` | 仅返回结构化候选；最终写库由应用执行 |
| Generator v6 | Extractor/规则完成后 | 同一次请求内自动 | 抽取结果、背景资产、技能与项目白名单 | 配置的 OpenAI-compatible `/chat/completions` | 仅提出诊断和路线；不能写文件、发消息或操作外部账户 |
| 本地规则回退 | 模型未配置、报错或门禁失败 | 自动 | 当前请求和代码目录 | 无外部 API | 生成保守结果并继续写分析记录 |

模型没有工具调用能力，不能浏览网页、执行代码、操作数据库或主动联系用户。

## Steering 与硬门禁

- Steering：`evals/prompts/extractor_v5.txt` 与 `evals/prompts/generator_v6.txt` 定义角色、JSON 合同和写作要求。
- 非提示词硬门禁：`evals/gates.py` 和 `backend/app.py` 强制技能/项目白名单、背景依据、必选重点技能、结构字段、未来式简历句、禁止 offer 承诺、禁止无依据量化成果。
- 匹配分由应用规则计算，不接受模型给出的分数。
- 模型输出经 JSON 解析、归一化和验证后才能进入结果；门禁失败即丢弃并使用回退，不做“尽量展示”。

## 输出合同与失败处理

- Extractor 输出必须匹配技能本体、证据和优先级要求；生产路径若调用失败会退回本地抽取。
- Generator 输出由 `validate_generator_output` 检查，且只允许从应用提供的项目/技能集合选择。
- 单次模型请求超时 90 秒，客户端最多尝试两次；不支持 `response_format` 的服务在 HTTP 400 时降级为普通 JSON 提示。
- `model_runs` 记录角色、模型、耗时、token、schema 状态和截断错误，不记录 API key。
- 面向用户的 `source` 标记结果来自模型还是规则回退。

## 控制项现状

| 控制 | 当前状态 |
|---|---|
| 用户批准 | 有：只有用户点击提交才启动，不存在后台自主运行 |
| 白名单与 schema | 有：代码硬门禁 |
| 重试与超时 | 有：90 秒、一次重试 |
| 审计 | 部分：模型运行元数据入库，无管理员查看界面和集中日志 |
| 速率限制 | 无 |
| 费用上限 | 应在供应商控制台配置，应用内无预算熔断 |
| Kill switch | 清空模型 profile/key 后自动走本地规则；无单独开关 |
| 内容隐私 | 无脱敏层；请求原文会发送给第三方供应商 |

上线前至少应加入每 IP/账号限流、供应商额度告警、明确的 `MODEL_ENABLED=false` 开关，并验证所有回退路径。
