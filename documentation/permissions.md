# 权限模型

## 角色与权限来源

| 角色 | 识别方式 | 说明 |
|---|---|---|
| 访客 | 无有效令牌 | 可使用公开内容并匿名提交分析 |
| 登录用户 | HMAC 令牌中的 `sub`、`email`、`exp` | 可读取属于自己的历史分析 |
| 服务端进程 | 部署环境变量 | 可读模型密钥和读写整个 SQLite 数据库 |

当前没有管理员角色、组织、付费权限或数据库 RLS。所有用户数据隔离均由 `backend/app.py` 的查询条件执行。

## 资源 × 操作矩阵

| 资源 / 操作 | 访客 | 登录用户 | 服务端 |
|---|---:|---:|---:|
| 健康状态 / 读取 | 允许 | 允许 | 允许 |
| 项目目录 / 读取 | 允许 | 允许 | 允许 |
| 通用谈资 / 读取 | 允许 | 允许 | 允许 |
| 个性化最近谈资 / 读取 | 禁止 | 仅本人 | 允许 |
| 新分析 / 创建 | 允许，归属为空 | 允许，归属本人 | 允许 |
| 分析历史 / 列表 | 禁止 | 仅本人 | 允许 |
| 单份分析 / 读取 | 禁止 | 仅本人 | 允许 |
| 用户 / 创建 | 允许注册 | 允许但无额外意义 | 允许 |
| 用户 / 列表、修改、删除 | 无接口 | 无接口 | 可直接访问数据库 |
| 模型配置与密钥 / 读取 | 禁止 | 禁止 | 允许 |

## 强制规则

- 受保护接口必须使用 `require_user`，不能仅解析可选令牌。
- 分析列表必须按令牌 `sub` 限制 `user_id`。
- 单份分析必须同时按记录 ID 和令牌 `sub` 查询。
- 健康接口只能返回配置状态、模型名和 profile 名，不得返回 base URL 密钥或令牌密钥。
- 前端构建产物不得包含任何 `*_API_KEY` 或 `TOKEN_SECRET`。

## 当前限制

- 无账号删除、密码重置、邮箱验证、令牌撤销和会话设备管理。
- 无针对匿名分析的读取令牌；匿名结果只在创建响应中可见。
- 无数据库层第二道隔离防线，API 查询回归会直接造成越权风险。
