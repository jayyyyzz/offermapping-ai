# 小规模探索性验证计划

这份模板用于记录 5–10 个经过授权、脱敏的真实求职案例。当前仓库不包含真实个人简历或招聘方资料，也不把合成样例当作真实验证结果。

## 使用前提

- 每位参与者明确同意将 JD 与简历用于本项目的离线评估；记录同意日期、用途和撤回方式。
- 删除姓名、电话、邮箱、公司内部项目名、客户名、链接中的个人标识等直接或间接识别信息。
- 若启用第三方模型，单独确认参与者知悉输入可能被传输给模型服务商；默认优先使用无密钥规则链路。
- 评估结束后按参与者要求删除原始文本、导出文件和临时数据库。

## 案例登记表

每个案例使用一个随机编号（例如 `case-01`），不要在仓库中记录真实姓名。

| 字段 | 内容 |
| --- | --- |
| case_id | `case-01` … `case-10` |
| role_family | 脱敏后的岗位族，例如“后端工程” |
| seniority | 校招 / 1–3 年 / 3–5 年 |
| consent_ref | 外部授权记录编号，不放原始授权文件 |
| input_source | 参与者提供 / 公开 JD（需注明来源） |
| model_mode | `rules` / `model-assisted` |
| reviewer | 两名人工复核者的匿名代号 |
| review_date | YYYY-MM-DD |

## 人工复核量表

对每个案例分别标注以下项目，并保留能回到输入文本的句子或段落位置：

1. 岗位族是否合理（正确 / 部分正确 / 错误）。
2. 技能证据等级是否准确：`project-backed`、`listed-only`、`missing`。
3. 优先级是否与 JD 的硬门槛和加分项一致。
4. 推荐项目是否来自已核验目录，是否存在不可验证或夸大的表述。
5. 报告是否给出可执行的下一步，而不是承诺录用或 offer。

建议由第二位复核者盲评 20% 的案例，记录分歧并在讨论后形成最终标签。汇总时至少报告：岗位族准确率、技能证据准确率、证据过度声明率、引用可追溯率，以及每个案例的主要分歧。

## 结果声明模板

> 本次评估包含 **N** 个经授权、脱敏的真实案例，属于小规模探索性验证，不代表招聘结果预测能力，也不能外推到其他岗位或人群。所有指标均基于本次人工复核样本，后续需要更大、更多样的独立数据集复验。

在没有完成授权与人工复核前，请在 README、简历和面试说明中保留“真实案例验证尚未完成”，不要填写推测性的准确率。
