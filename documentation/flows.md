# 关键流程

## 1. 匿名或登录用户提交分析

- 参与者：访客或登录用户
- 前置条件：JD 50–8,000 字符，简历 100–10,000 字符
- 成功结果：返回分析报告，并写入分析及模型运行记录

1. 浏览器向 `POST /api/analyses` 发送 JD、简历；登录用户附带 Bearer 令牌。
2. API 校验长度。令牌可选：有效则得到 `user_id`，无效令牌按匿名请求处理。
3. 服务端调用 Extractor，将 JD/简历发送到模型供应商；失败则用本地规则抽取。
4. 服务端计算匹配分、候选技能和项目白名单。
5. 服务端调用 Generator，并对返回 JSON 执行硬门禁；不合格则使用安全回退。
6. 服务端把原始 JD、原始简历、完整结果写入 `analyses`，把模型、耗时、token、schema 状态和错误写入 `model_runs`。
7. 浏览器展示结果。

信任边界：浏览器→API、API→第三方模型、模型输出→硬门禁、API→数据库。副作用：第三方数据传输、数据库写入和模型费用。当前没有用户确认第三方传输的独立勾选项，也没有请求速率限制。

## 2. 注册与登录

- 参与者：访客
- 前置条件：合法邮箱、8–128 位密码
- 成功结果：返回 7 天有效的签名令牌

注册时服务端规范化邮箱、校验格式、哈希密码并创建用户；重复邮箱返回 409。登录时读取用户并验证哈希；失败返回 401。浏览器把令牌存入 `localStorage`。

信任边界：浏览器→API、API→数据库。副作用：注册会写用户表。拒绝路径：非法邮箱、重复邮箱、错误密码、过期或被篡改令牌。

## 3. 查看个人历史和单份报告

- 参与者：登录用户
- 前置条件：有效 Bearer 令牌
- 成功结果：仅返回当前用户拥有的记录

1. `require_user` 验签并检查过期时间；失败返回 401。
2. 列表查询固定加入 `WHERE user_id=?`。
3. 单份报告查询同时限制 `id=? AND user_id=?`；越权或不存在统一返回 404。

授权依据来自令牌 `sub`，数据库没有 RLS。关键拒绝用例是用户 A 访问用户 B 的分析 ID，必须返回 404。

## 4. 浏览项目与谈资

- 参与者：任何访客；登录用户可获得与最近报告相关的谈资
- 前置条件：无
- 成功结果：读取代码内项目目录和简报数据

项目接口是公开只读接口。谈资接口在令牌有效时读取当前用户最新分析，否则返回默认岗位族内容。无数据库写入；当前简报是静态目录数据，不是实时新闻抓取。

## 5. 启动生产部署

1. 构建阶段执行 `npm ci` 和前端生产构建。
2. 运行阶段安装 Python 依赖并以非 root 用户启动 Uvicorn。
3. `APP_ENV=production` 时校验强 `TOKEN_SECRET`。
4. FastAPI 初始化 SQLite，并在 `dist/` 存在时同源托管网页。
5. `/api/health` 暴露服务版本和模型是否配置，不返回密钥。

副作用：首次启动创建数据库表。运维拒绝路径：生产密钥缺失或过短时进程直接失败。
